# SCG Green Products (GreenCat)

เว็บแสดงข้อมูลสินค้า SCG Green Products: ฉลาก/ใบรับรองอาคารเขียวของสินค้าแต่ละตัว พร้อมเอกสาร (EPD, CFP, ฉลากเขียว ฯลฯ) และเครื่องมือตรวจคุณภาพข้อมูลสำหรับทีมงาน

- **เว็บจริง:** https://poroma.github.io/GreenCat/
- **หน้าแปลงไฟล์ (Convert):** https://poroma.github.io/GreenCat/Convert/
- **รูปแบบ:** เว็บ Static ล้วน (HTML + JavaScript ในไฟล์เดียว) ไม่มี Server และไม่มีขั้นตอน Build ข้อมูลดึงจาก Google Drive ตรงจากเบราว์เซอร์

## หน้าต่างๆ และใครเห็นอะไร

หน้า Login มี 2 แท็บ:

| | External (ค่าเริ่มต้น) | Internal (พนักงาน SCG) |
|---|---|---|
| วิธีเข้า | กด "เข้าใช้งานโดยไม่ใช้บัญชี" | Login ด้วย Username / Password จาก `users.js` |
| ป้ายมุมขวาบน | 🌐 External (Read-only) | ชื่อผู้ใช้ |
| ตารางสินค้า (Main) | ✓ | ✓ |
| ขอข้อมูลเพิ่มเติม (ฟอร์ม) | ✓ | – |
| เมนู Document / Health Check / Setting | – | ✓ |

| หน้า | ใช้ทำอะไร |
|---|---|
| **Main** | ตารางสินค้า × Green Attributes × ใบรับรอง (LEED / TREES / WELL ฯลฯ) ค้นหา กรอง Highlight และ Export Excel ได้ |
| **ช่องติ๊กหน้าชื่อสินค้า** | ติ๊กเลือกได้หลายสินค้า (คลิกแถวก็ได้) → แถบลอย "เลือกแล้ว N รายการ" · External: ปุ่ม "ขอข้อมูลสินค้านี้" · Internal: ปุ่ม "ดูเอกสาร" เปิด Pop-up เอกสารของทุกสินค้าที่เลือก (ลิงก์เปิดไฟล์, วันหมดอายุ, เอกสารบังคับของ BU ที่ยังขาด, ลิงก์ไปหน้า Document) |
| **ขอข้อมูลเพิ่มเติม** | (External) ติ๊กสินค้าในตาราง → แถบลอย "ขอข้อมูลสินค้านี้" → ฟอร์มที่เติมสินค้าให้เอง ค้นหาเพิ่มได้ · ช่องในฟอร์ม: สินค้า, ชื่อ\*, นามสกุล, อีเมล/เบอร์\* (อย่างน้อย 1), จังหวัด, หัวข้อที่สนใจ, วัน/เวลาสะดวก, ความยินยอม PDPA\* |
| **Document** | รายการเอกสารของสินค้าแต่ละตัว (จาก Link Master) พร้อมสถานะหมดอายุ |
| **Health Check** | คะแนนคุณภาพข้อมูล ปัญหาที่พบ (ชื่อไฟล์ผิดรูปแบบ, เอกสารหมดอายุ, ลิงก์ผิด ฯลฯ) และสินค้าที่เอกสารยังไม่ครบตาม BU · Export เป็น Excel ได้ |
| **Setting** | ตั้งกติกาที่ Health Check ใช้: รูปแบบชื่อไฟล์, ประเภทเอกสาร/BU ที่อนุญาต, เอกสารบังคับต่อ BU, วันหมดอายุ, ลิงก์ |
| **Convert** | แปลงไฟล์ต้นทางเป็นไฟล์ที่เว็บอ่าน แล้วบันทึกขึ้น Google Drive |

## ข้อมูลมาจากไหน

```
ไฟล์ต้นทาง (Excel)                 หน้า Convert                Google Drive              เว็บ
─────────────────────             ─────────────              ────────────              ─────
Product Data (แบบกว้าง)    ──►  โหมด Master        ──►   Master.xlsx        ──►  Main
SCG Green Products Directory ──►  โหมด Linked Master ──►   Link Master.xlsx   ──►  Document / Health Check
   (Sheet "Link เอกสาร")
```

- เว็บอ่านไฟล์บน Drive ด้วย **File ID** (ไม่ใช่ชื่อไฟล์) จึงเปลี่ยนชื่อไฟล์บน Drive ได้ แต่ **ห้ามลบแล้วอัปโหลดใหม่** เพราะ ID จะเปลี่ยน
- ไฟล์บน Drive ต้องแชร์เป็น **Anyone with the link: Viewer**

### วิธีอัปเดตข้อมูล

1. เปิดหน้า [Convert](https://poroma.github.io/GreenCat/Convert/) แล้วเลือกโหมด (Master หรือ Linked Master)
2. เลือกไฟล์ต้นทางจากเครื่อง ระบบเลือก Sheet ให้อัตโนมัติ ("Product Data" หรือ "Link เอกสาร")
3. ตรวจตัวเลขสรุป แล้วกด **Save ลง Google Drive** (ต้อง Login Google บัญชีที่มีสิทธิ์แก้ไขไฟล์)
4. ผู้ใช้จะเห็นข้อมูลใหม่ในการเปิดเว็บครั้งถัดไป (ดูหัวข้อ Cache)

หน้า Convert บีบอัดไฟล์ในเบราว์เซอร์ก่อนส่งขึ้น Drive (Master ~17 MB → ~3 MB) ไฟล์ยังเปิดใน Excel ได้ตามปกติ

### Pop-up เอกสารของสินค้า (Internal) จับคู่สินค้ากับเอกสารอย่างไร

ตาราง Main (Master.xlsx) กับ Link Master ใช้รหัส BU ต่างกัน (เช่น SCG ↔ CGS, SCG Roof ↔ ROOF) จึงจับคู่ด้วย **ชื่อสินค้า**:

1. ชื่อในคอลัมน์ "Products" ตรงกับ Group Name หรือ [TH]/[EN] Product Name ใน Link Master (ไม่สนตัวพิมพ์เล็ก-ใหญ่/ช่องว่าง)
2. ถ้าไม่ตรง: ตัดข้อความในวงเล็บออกแล้วเทียบใหม่ (เช่น "สกิมโคท... (สีเทา)" และ "(สีขาว)" → แสดงทั้งสองชุด)
3. ถ้ายังไม่ตรง: ยอมให้ต่างกัน 1 คำ คือมีคำเกินมา 1 คำ (เช่น "DECAAR") หรือเป็นคำเดียวกันคนละภาษา ไทย ↔ อังกฤษ (เช่น "เดคาร์" ↔ "DECAAR") **ไม่ยอมให้ต่างกันที่คำซึ่งมีตัวเลข** กันจับผิดรุ่น/ขนาด

ข้อ 2–3 จะขึ้นป้าย "จับคู่โดยประมาณ" ใน Pop-up ข้อมูล 23 พ.ย. 2026: จับคู่ได้ 186 จาก 343 สินค้า (ตรงทุกตัวอักษร 162 + โดยประมาณ 24) ที่เหลือคือสินค้าที่ Link Master ยังไม่มีเอกสารเลย (NPI, CPAC, COTTO, SGI, Windsor ฯลฯ)

**ถ้า Pop-up ขึ้นว่า "ยังไม่พบเอกสาร" ทั้งที่มีเอกสาร** ให้แก้ชื่อสินค้าใน Sheet "Link เอกสาร" (Group Name หรือ [TH] Product Name) ให้ตรงกับชื่อในตาราง Main

## Health Check: ตรวจว่าสินค้าไหนเอกสารยังไม่ครบ

ระบบเทียบข้อมูล 2 แหล่ง:

**1. "ต้องมีอะไร": ตาราง "เอกสารบังคับต่อ BU" ในหน้า Setting**

| BU | เอกสารบังคับ (ค่าเริ่มต้น) |
|---|---|
| CGS | CFP, EPD |
| LS | CFP |
| SFG | Asb, EPD, GrCh |
| CW | EPD, CFP |
| ROOF | CFP, GrCh |
| QCON | CFP, GrCh, CFR |
| SCI | VOC |

- ค่าเริ่มต้นตั้งจากข้อมูลจริงใน Link Master (17 พ.ย. 2026): ถ้าสินค้าเกินครึ่งหนึ่งใน BU มีเอกสารประเภทนั้นอยู่แล้ว ก็ถือเป็นเอกสารบังคับของ BU นั้น
- แก้ได้ในหน้า Setting โดยติ๊กในตาราง หรือกดปุ่มเติมอัตโนมัติ (ใช้เกณฑ์เดียวกัน) ค่าเริ่มต้นในโค้ดอยู่ที่ `DEFAULT_SETTINGS.completeness.requiredDocs`
- BU ที่ไม่ได้ตั้งไว้จะไม่ถูกเช็คความครบ

**2. "มีอะไรแล้ว": ไฟล์ Link Master (มาจาก Sheet "Link เอกสาร")**

| ข้อมูล | อ่านจาก |
|---|---|
| สินค้า | คู่ **BUs + Group Name** (สะกดต่างกันแม้แค่เว้นวรรค = คนละสินค้า) |
| Tag ประเภทเอกสาร (EPD, CFP, GrCh ฯลฯ) | คอลัมน์ **"ประเภทเอกสาร"** ตรงๆ (ไม่ได้เดาจากชื่อไฟล์ · ถ้าว่างจะเป็น "อื่นๆ") |
| วันหมดอายุ | **ชื่อไฟล์เอกสาร** ตามรูปแบบชื่อไฟล์ที่ตั้งในหน้า Setting |

**ความหมายของ Tag ในรายการสินค้า**

| Tag | ความหมาย |
|---|---|
| EPD ✓ (เขียว) | มีเอกสารประเภทนั้นอย่างน้อย 1 ไฟล์ |
| EPD หมดอายุ (ส้ม) | มีเอกสาร แต่ทุกไฟล์หมดอายุแล้ว นับเป็น "ขาด" ด้วย (ปิดได้ใน Setting) |
| EPD ขาด (แดง) | ไม่มีเอกสารประเภทนั้นเลย |

ช่อง "เอกสารอื่น" = ประเภทที่สินค้ามี แต่ไม่ได้อยู่ในรายการบังคับของ BU นั้น

### เมื่อสินค้าเพิ่มขึ้น ต้องอัปเดตเองไหม

**ไม่ต้อง** เพราะกติกาตั้งไว้ระดับ BU ไม่ได้ตั้งทีละสินค้า สินค้าใหม่ใน BU เดิมแค่ใส่แถวใน Sheet "Link เอกสาร" แล้ว Convert ตามปกติ Health Check จะเช็คให้อัตโนมัติ

ต้องเข้าไปแก้ในหน้า Setting เฉพาะกรณีเหล่านี้:

| กรณี | ถ้าไม่แก้ |
|---|---|
| มี **BU ใหม่** | สินค้าของ BU นั้นไม่ถูกเช็คความครบ (หน้า "สรุปตาม BU" ขึ้นว่า "ไม่ได้ตั้ง") |
| มี **ประเภทเอกสารใหม่** | หน้า Setting ติดป้าย "พบใหม่" ให้ กดเพิ่มได้ทันที |
| **นโยบายเปลี่ยน** (เช่น LS ต้องมี EPD เพิ่ม) | ยังเช็คตามกติกาเดิม |

### ข้อควรระวัง

- **คอลัมน์ "ประเภทเอกสาร" ต้องกรอกตรงกับรายการที่อนุญาต:** ถ้าพิมพ์ผิด (เช่น "GreenChoice" แทน "GrCh") หรือเว้นว่าง ระบบจะขึ้นว่า "ขาด" ทั้งที่มีไฟล์อยู่ ส่วน Health Check จะแจ้งกรณีนี้ในหัวข้อ "ประเภทเอกสารไม่อยู่ในรายการที่อนุญาต"
- **Group Name ต้องสะกดเหมือนกันทุกแถว:** ถ้าต่างกันแม้แค่เว้นวรรค ระบบจะมองเป็นคนละสินค้า
- **ค่าที่แก้ในหน้า Setting เก็บในเบราว์เซอร์ของคนที่แก้เท่านั้น:** คนอื่นยังเห็นค่าเดิม (ดู "ข้อจำกัดที่ควรรู้")

## Cache (ทำให้เปิดเว็บเร็ว)

- เปิดครั้งแรก: ดาวน์โหลดไฟล์จาก Drive แล้วเก็บไว้ในเบราว์เซอร์ (IndexedDB)
- เปิดครั้งถัดไป: แสดงข้อมูลที่เก็บไว้ทันที แล้วเช็คกับ Drive แค่ "เวลาแก้ไขล่าสุด" ของไฟล์ ดาวน์โหลดใหม่เฉพาะเมื่อไฟล์เปลี่ยน
- ถ้ามีข้อมูลใหม่ระหว่างที่ผู้ใช้กำลังใช้ตาราง จะขึ้นปุ่ม "มีข้อมูลใหม่" ให้กดเอง (ไม่สลับข้อมูลกลางคัน)
- ปุ่มรีเฟรช = บังคับดาวน์โหลดใหม่ · **ออกจากระบบ = ล้าง Cache ทั้งหมด**

## Deploy

- GitHub Pages Deploy จาก Branch `main` อัตโนมัติ หลัง Merge ประมาณ 1–2 นาที
- ถ้าเปิดแล้วยังเห็นหน้าเก่า กด **Ctrl+Shift+R**
- แนวทางทำงาน: แตก Branch → Commit → เปิด Pull Request → Merge เข้า `main`

### ทดสอบในเครื่อง

เปิดผ่าน Local Server (ไม่ใช่ดับเบิลคลิกไฟล์) เพื่อให้ Cache และการดึง Drive ทำงานเหมือนเว็บจริง:

```bash
python -m http.server 8000
# แล้วเปิด http://localhost:8000/
```

### ข้อควรระวังเวลาแก้โค้ด

- `index.html` ใช้ Line ending แบบ **CRLF** ให้คงไว้แบบเดิม
- หัวตารางกับเนื้อตารางเป็นคนละ `<table>` กัน และคุมความกว้างด้วย `<colgroup>` อย่าเพิ่ม padding/เนื้อหาที่ดันความกว้างคอลัมน์
- คอลัมน์ข้อมูลสินค้าทางซ้ายใช้ `position: sticky` + ค่า `left` ที่คำนวณจาก JS **ห้ามตั้ง `position` อื่นทับ** ไม่งั้นคอลัมน์จะเลื่อนผิดตำแหน่ง

## ข้อจำกัดที่ควรรู้

- **Login เป็นแค่การกันหน้าฝั่ง Client** ไม่ใช่ระบบความปลอดภัยจริง: ใครเปิด `users.js` ก็เห็นรหัสผ่าน และไฟล์บน Drive เปิดได้ทุกคนที่มีลิงก์ ห้ามใส่ข้อมูลลับ
- **ฟอร์มขอข้อมูลยังเป็นโหมดทดสอบ** จนกว่าจะตั้ง `LEAD_FORM_CONFIG.endpoint` (แนะนำ Google Apps Script ที่บันทึกลง Google Sheet)
- **ค่าใน Setting เก็บในเบราว์เซอร์ของแต่ละคน** (localStorage) ยังไม่แชร์ระหว่างผู้ใช้ แผนต่อไปคือเก็บเป็น `settings.json` บน Drive
- **ตารางผู้ใช้ (Username, Email, Password Hash, Role)** ในหน้า Setting เป็นโครงสร้างที่วางไว้ ยังไม่ได้ใช้ Login จริง
